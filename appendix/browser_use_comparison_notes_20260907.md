**EH × Browser Use：对照配置与判定说明**

本页补充[实测文章](../blog.md)中的六对对照。数据来自 2026 年 7 月 14 日冻结的 RXT → SEC 任务记录；这里只整理既有运行，不重新查询今天的行情与申报文件。

任务要求从 Investing 首页进入 RXT 行情页，读取页面显示的公司、代码、报价及成交量等字段，再从 SEC 首页通过可见入口找到指定公司的最新 8-K 与 EX-99.1。两臂均禁止构造申报结果深链、读取旧实验答案、登录、下载、下单或支付。

**运行条件**

| 条件 | EH | Browser Use |
|---|---|---|
| 模型名称 | DeepSeek V4 Pro | DeepSeek V4 Pro |
| 推理配置记录 | OpenCode 启动参数为 `variant=max`，表示本次选择的推理档位 | 冻结适配层与运行配置未显式记录同一推理档位，等价性未确认 |
| 页面输入与执行 | 文本契约，普通单动作，动作后感知 | 文本模式，关闭视觉与内置 judge |
| 执行预算 | 每会话 24 次动作尝试、24 次感知；Investing 与 SEC 分会话 | 整项任务最多 24 个代理步骤，每步最多 5 个动作 |
| 其他停止配置 | 两个会话各完成一次终局交付后停止 | 900 秒超时，最大失败次数配置为 3 |
| 其他 BU 设置 | — | 开启规划、消息压缩、循环检测；经冻结的 DeepSeek 适配层使用 JSON 对象与结构化输出 schema |
| 版本记录 | 代码提交 `aa87ca0e35d8ff0d0d6b42a7e3fb2f4fefe02d0e` | 同一代码冻结窗；记录字段为 `browser_use_version=0.13.4`、`browser_use_core_version=0.13.2` |

Browser Use 六次运行的上述配置字段一致。两个版本字段由当时的适配代码写入，应作为运行记录引用，尚不能替代安装包版本核验。模型名称一致也不足以证明推理档位一致；24 个代理步骤与每会话 24 次动作尝试的预算单位不同。

每次运行前按同一规则清理任务站点状态，回到唯一空白页。六对顺序为 EH→BU、BU→EH 交替，两臂各先手三次；经验检索与写入关闭，代码与任务材料在每对运行前后进行冻结检查。11 个相邻运行间隔由清场时间和任务墙钟重建，为 300.298–301.783 秒；冷却时间未计入任务墙钟。

**配置可比性的范围**

这组对比由项目方组织。正式六对前做过先导测试，先导批次不进入本表统计；正式批次中两套配置按冻结材料运行。EH 任务卡包含分段查询、在离开报价区域前冻结证据、终局字段绑定等执行指引；BU 使用本地 DeepSeek 适配层，将结构化输出 schema 交给模型。模型名称、任务目标、起点清理与外部质量门保持一致，提示内容、推理档位证据、执行预算及终局机制则未完全对齐。

因此，结果包括任务提示与适配配置的影响，不能单独归因为框架能力差异，也不能描述成双方未经适配或调优的默认配置对照。BU 记录中的 `mode=fair` 只是本地运行器对文本模式、关闭内置 judge 这一组合的命名，不代表实验公平性已被独立证明。其他配置下的 BU 表现需要另行测试。

**质量门检查的内容**

两臂最终输出交给同一确定性函数检查。质量门要求完成标记成立，14 个必需数据字段非空且未填 unavailable 等缺失标记，并检查以下条件：

- 公司名包含 Rackspace Technology，代码为 RXT，CIK 包含指定公司标识。
- Filing Date 与 Accepted 的字符串长度符合预设要求。
- Items 包含 1.01、2.02、2.03、8.01、9.01。
- EX-99.1 描述包含 press release。

EH 的完成标记取自两个会话的终局状态，BU 的完成标记取自结构化最终输出。统一质量门作用于各自导出的字段，不能消除两套执行框架的终局处理差异。

这套检查未自动将每个行情数值与页面逐项对照，也未独立确认申报文件是当时最新、日期内容正确或证据 URL 确实支持每个字段。这些判断需要进一步结合各轮冻结页面和操作轨迹。表内“通过”指通过上述质量门；它与 NL50 的原冻结用户交付层是不同任务、不同判定流程的读数，不能合并计算成功率。

EH 六轮均通过质量门，Browser Use 一轮通过；两臂六轮总模型费用分别为 0.282184 与 0.406504 美元。总费用包含未通过轮的投入，并按未舍入记录汇总，可能与表中逐轮显示值相加略有差异。成本依据本次冻结价卡与调用 usage 记录，未计入硬件、网络、人工或冷却时间成本。

Browser Use 的未通过轮在原轨迹复核中分为三类：第 1 对在 SEC 入口之间绕行后未形成结果；第 2、4 对终局字段不全；第 5、6 对选到了旧申报或错误类型对象，未恢复出符合要求的最终结果。第 2、4、5、6 对均在进入 SEC 阶段后的首个动作选中正确的 EDGAR 入口，但随后未通过质量门；第 3 对在入口阶段绕行了 2 步，最终通过。这些是该任务中的观察，不能推成框架在所有网页上的固有缺陷。

六对里有五对 EH 的墙钟和模型费用更低。第 1 对方向相反，EH 在 SEC 入口绕行了 8 步。唯一两边都通过质量门的第 3 对中，EH 墙钟低约 4.99%、费用低约 5.49%，调用数则为 22 对 21，reasoning token 为 13,008 对 12,396。两臂执行模式、预算单位及终局机制不同，加上固定单任务、六次重复的样本规模，结果只适合描述这一配置下的观察。
